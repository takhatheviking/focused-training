# Focused Event Bot

Telegram-бот ивентов focused.uz: афиша, бронь мест, оплата переводом на карту с проверкой чека модератором, билеты с QR-кодом и проверка на входе. Интерфейс на русском, узбекском и английском.

Как устроено внутри — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Запуск в Docker

1. Создайте бота у [@BotFather](https://t.me/BotFather) и скопируйте токен.
2. `cp .env.example .env`, впишите `BOT_TOKEN` и свой Telegram id в `ADMIN_IDS` (id можно узнать у @userinfobot). Для продакшена поменяйте `POSTGRES_PASSWORD`.
3. Запустите:

```bash
docker compose up -d --build
```

Миграции применяются при старте контейнера. Логи: `docker compose logs -f bot`.

## Первая настройка (в самом боте)

1. `/start` → выберите язык → «⚙️ Админка».
2. **💳 Карта для оплаты** — номер карты, получатель, банк. Пока карты нет, платные брони закрыты.
3. **🛡 Чат модерации** — создайте закрытый канал (или группу) для модераторов и добавьте бота администратором с правами «публиковать» и «редактировать сообщения». Бот сам напишет вам в личку и предложит использовать этот чат. Пока чат не подключён, чеки приходят админам в личку.
4. **👥 Команда** — добавьте контролёров, которые будут сканировать билеты на входе.
5. **➕ Новый ивент**: бот присылает форму. Скопируйте её, заполните и отправьте одним сообщением. В форме:
   - название, описание и место — на RU, UZ и EN;
   - дата, ссылка на карту, цена, количество мест.

   Следующим шагом бот попросит афишу, потом покажет предпросмотр. Если перевод UZ или EN не заполнен, пользователи этого языка увидят русский текст, и предпросмотр об этом предупредит. Кнопка «📋 Пример» показывает заполненную форму.
   Потом можно добавить типы билетов (VIP и т.п., название тоже на трёх языках: `VIP / VIP / VIP`) и скопировать ссылку для анонса: `t.me/<бот>?start=ev_<id>`. Чтобы исправить ивент, нажмите «✏️ Изменить → 📝 Тексты, дата, карта»: бот пришлёт текущую форму уже заполненной.

6. **📗 Google Таблица** (по желанию) — бот сам ведёт таблицу с участниками по каждому ивенту и всеми заказами. Как подключить — [docs/GOOGLE_SHEETS.md](docs/GOOGLE_SHEETS.md).

## Билеты без оплаты (гости, спикеры, наличные)

На карточке ивента нажмите «🎫 Выдать билет», выберите тип билета и количество. Затем укажите получателя одним из способов:

- **Написать имя гостя.** Можно сразу с телефоном: `Иван Петров, +998901234567`. Билет придёт вам, перешлите его гостю.
- **«👤 Выбрать из Telegram».** Билет придёт человеку в бот. Если он бота ещё не открывал, Telegram не даёт написать первым, и билет придёт вам.

Место списывается из лимита ивента. Можно выдавать билеты скрытого типа: так удобно держать отдельную квоту, например тип «Гость / Mehmon / Guest», снятый с продажи. Выданные вручную билеты считаются отдельно от проданных: в карточке ивента это строка «выдано вручную», в отчёте и Google Таблице — способ оплаты «Выдан вручную» и кто выдал.

## Как проходит покупка

1. Пользователь выбирает ивент → «Купить билет» → количество → делится номером телефона (один раз) → подтверждает бронь.
2. Бот показывает сумму и карту, места держатся 30 минут.
3. Пользователь переводит деньги и присылает скрин или PDF чека.
4. Чек появляется в чате модерации с кнопками ✅ / ❌. Модератор находит в банковском приложении перевод **ровно на сумму из карточки**: суммы у заказов разные, поэтому один перевод не подойдёт к двум заказам. Причины отказа: сумма не совпадает, чек нечитаемый, платёж не поступил, другое. После отказа у пользователя есть ещё попытки (по умолчанию всего 3).
   Если сообщение с чеком потерялось, его можно отправить заново: «⚙️ Админка → 🧾 Чеки на проверке». Заказы, по которым нужно вернуть деньги, собраны в «💸 Возвраты».
5. После одобрения пользователь получает билеты: картинку с QR и кодом.
6. На входе контролёр сканирует QR камерой телефона, открывается бот с карточкой билета и кнопкой «✅ Впустить». Код можно ввести и вручную: «📷 Проверка билетов».

## Локальная разработка

Нужны Python 3.12+, [uv](https://docs.astral.sh/uv/) и Docker (для PostgreSQL).

```bash
uv sync
```

```bash
docker compose up -d db
```

```bash
uv run alembic upgrade head
```

```bash
uv run python -m app
```

Тесты (идут на настоящем PostgreSQL, тестовая база `focused_bot_test` создаётся сама):

```bash
uv run pytest
```

Новая миграция после изменения моделей:

```bash
uv run alembic revision --autogenerate -m "описание"
```

## Настройки `.env`

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `BOT_TOKEN` | — | токен бота |
| `ADMIN_IDS` | — | Telegram id суперадминов через запятую |
| `DATABASE_URL` | localhost | строка подключения PostgreSQL (asyncpg) |
| `REDIS_URL` | — | хранилище шагов диалогов; без него — в памяти |
| `TIMEZONE` | `Asia/Tashkent` | в нём вводятся и показываются даты |
| `DEFAULT_LANG` | `ru` | язык до выбора и язык чата модерации |
| `HOLD_MINUTES` | `30` | сколько держится бронь без чека |
| `MAX_PROOF_ATTEMPTS` | `3` | сколько раз можно прислать чек после отказов |
| `MAX_TICKETS_PER_ORDER` | `5` | максимум билетов на человека на один ивент |
| `UNIQUE_AMOUNTS` | `true` | от суммы каждого заказа отнимается 1–99 сум, чтобы перевод однозначно находился в банке |
| `REVIEW_ALERT_MINUTES` | `120` | через сколько минут без решения по чеку напомнить админам |
| `SUPPORT_USERNAME` | — | контакт поддержки в /help и сообщениях о возврате |
| `PAYMENT_CARD_*`, `MODERATION_CHAT_ID` | — | запасные значения; обычно задаются из админки |
